## 2. Concurrency
- **Parallel, capped at 2**: `private const int MaxConcurrentDownloads = 2;` with `SemaphoreSlim _semaphore` (`DownloadQueueService.cs:14,18`). Each item's *entire lifecycle* (resolve + download + post-process) holds one slot.
- **Locks used**: `lock (_resolvedUrlCache)` in WingetStoreService (:80,97), `lock (_activeTasks)` (:387,457), `lock (_saveLock)` around SaveQueue (:203). `Interlocked` for `_pendingCount` (:889-899).
- `_queue` is an `ObservableCollection<DownloadItem>` mutated only on the UI thread (all mutations go through the UI thread; `LoadQueue` marshals adds via `TryEnqueue`, :310-317).
- **Not sequential** — 2 items download simultaneously; additional items wait at `WaitAsync` in `StartItemAsync:372`. Note waiting items are cancelled via the item's `Cts` token, handled by `OnDownloadPaused`.

## 3. Progress Reporting & UI Marshaling
- **Throttling**: `WriteDownloadStreamAsync` reports at most every 300 ms (:826), computing speed (Mbps) and ETA, and updating `item.ResumePosition` (:836).
- **Marshaling**: `DispatchState/DispatchProgress/DispatchProcessingStatus/DispatchCompleted/DispatchError` (:666-717) wrap every mutation in `_dispatcherQueue.TryEnqueue(...)` (set once in `MainWindow.xaml.cs:209` → `DownloadQueueService.Initialize(DispatcherQueue)`). Fallback: direct call if no dispatcher.
- **Events**: `DownloadItem` implements `INotifyPropertyChanged`; `QueueChanged` static event (`:44`) drives the MainWindow badge (`MainWindow.xaml.cs:375-397`, `UpdateDownloadBadge` reads `PendingCount`).
- **UI binding**:
- `DownloadQueueFlyout.xaml.cs:14-33` mirrors the service `_queue` into a *second* `ObservableCollection<DownloadItemViewModel>` (`Items`), subscribing to `Queue.CollectionChanged` + `QueueChanged`.
- `DownloadItemViewModel` (:147-265) subscribes to the item's `PropertyChanged` and re-raises `OnPropertyChanged("")` — a "refresh everything" hammer. The XAML (`DownloadQueueFlyout.xaml`) uses classic `{Binding}` (not `x:Bind`) on computed properties (`StateText`, `StatusLine`, `ProgressValue`, per-state button `Visibility` flags).
- `ToolsBundleDownloadDialog.xaml.cs:151-161` subscribes directly to `DownloadItem.PropertyChanged` for `State`/`Progress` and marshals with its own `DispatcherQueue.TryEnqueue`.
- **Smell**: multi-file path (`ProcessMultiFileAsync:525`) dispatches progress **per 80 KB read chunk with no throttle** (unlike the 300 ms throttle in the single-file path), flooding the dispatcher queue; its speed is always reported as 0.

## 4. Persistence / Resume
- **Path**: `%LOCALAPPDATA%...\download_queue.json` via `ConfigManager.GetDownloadQueuePath()` (`ConfigManager.cs:148`).
- **Save**: `SaveQueue()` (:201) serializes all items (id, urls, state, bytes, post-processor *key*). `MarkDirty()` (:329) sets `_dirty` and immediately `TryEnqueue(SaveQueue)` — i.e., save on every state change, on the UI thread. `_dirty` is otherwise unread (there's even a `#pragma warning disable CS0414` acknowledging it, :23-25) — no debouncing/coalescing.
- **Load**: on startup (`Initialize` → `Task.Run(LoadQueue)`, :40). Items that were `Downloading/Queued/Resolving` at save time are restored as **Paused** with `ResumePosition = BytesReceived` (:289-299); `Paused` restored as paused; `Completed/Failed/Cancelled` restored as-is.
- **Resume mechanics**: `DownloadFileAsync` (:744-773) checks the `.tubadl` partial file on disk, sends `Range: existingBytes-` header; only accepts `206 PartialContent` (sets `SupportsResume=true`), otherwise deletes the partial and restarts from 0. **The actual resume offset comes from the file size on disk, not `ResumePosition`** (the latter is only used for initial progress display) — which is actually a robust choice.
- **Integrity**: `ValidateDownloadedFile` (:623) opens every zip entry stream to check headers (zips only); corrupted files are deleted and re-downloaded. **No ETag/If-Range validation** — if the remote file changed between pause and resume, silent concatenation corruption is possible (mitigated only for zips).
- **Limitation**: only `DirectUrl` items survive restart. Resolver/multi-file items (tools bundle, app updates) are silently **dropped** at load (`:267` — `if (item is null) continue;` since their `DirectUrl` is null).
- **No save-on-exit flush**: `MainWindow` Closed only unsubscribes `QueueChanged` (:369); an enqueued `SaveQueue` that hasn't run when the process exits is lost.

## 5. Bugs and Code Smells
### Genuine race conditions
1. **Racy cancel/pause state check** — `DispatchState` is fire-and-forget marshaling, but `OnDownloadPaused` (:391) runs synchronously on the background thread when cancellation fires. In `Cancel()` (:114-133) for a `Queued` item: `DispatchState(Cancelled)` is *enqueued*, then the semaphore wait's `OperationCanceledException` handler calls `OnDownloadPaused` immediately — it may still see `Queued` (the Cancelled dispatch hasn't run yet) and enqueue `Paused` *after* `Cancelled`, plus `DecrementPending()` a second time. Result: wrong final state and `_pendingCount` drift (badge hides while items are pending; count can go negative).
2. **Pause→Resume double-task race** — `Resume()` (`:103`) replaces `item.Cts` and starts a new `StartItemAsync` while the *old* task may still be winding down (e.g., blocked in `stream.ReadAsync` before noticing cancellation). When the old task finally hits `catch (OperationCanceledException) → OnDownloadPaused`, it sees the new `Queued/Downloading` state and incorrectly marks the item `Paused` + decrements pending, even though the new task is still downloading.
3. **winget process stdout/stderr deadlock risk** — `GetInstallerUrlViaCliAsync` (`WingetStoreService.cs:277-294`) sets `RedirectStandardError = true` but **never reads stderr**; `SearchOnlineAsync` (:221-223) reads stdout to end *then* stderr sequentially. If winget writes enough to stderr to fill the pipe buffer while stdout is being drained, the child process blocks forever. Low probability with winget's small stderr output, but it's the textbook redirect deadlock.
### Missing cancellation / lifecycle issues
4. **`CancellationToken.None` for installs** — both store pages call `InstallPackageAsync(..., CancellationToken.None)`; navigating away doesn't cancel the `winget show` process or URL probing (the page's `_searchCts` only covers search).
5. **`Remove()` during `Processing` is a no-op** — it cancels the Cts and returns (`:150-154`), but post-processors largely ignore cancellation: `ArchiveExtractProcessor`'s `Task.Run(..., ct)` only prevents *start*; `InstallerLaunchProcessor` ignores `ct` entirely. The item is never actually removed and stays in the queue.
6. **`Cancel()` on a `Downloading` item yields `Paused`, not `Cancelled`** — only the Cts is cancelled; the state comes from `OnDownloadPaused`. The XAML hides the Cancel button unless Paused (`CancelVisible`, flyout VM :221), so it's worked around in the UI rather than fixed in the model.
7. **`UpdateInstallProcessor` calls `Application.Current.Exit()`** immediately after launching the updater (`DownloadQueueModels.cs:224`) — the "Completed" MarkDirty/save may be lost on exit.
### Unobserved / dead code
8. **`_activeTasks` is write-only** (`:20,387-388,457-458`) — tasks are stored and removed but never awaited or observed; dead bookkeeping. Combined with `StartItemAsync` being **`async void`** (:368), any exception escaping `ProcessItemAsync`'s try (it can't currently, but the pattern is fragile) would crash the process.
9. Fire-and-forget without observation: `_ = Task.Run(() => LoadQueue())` (:40), `_ = dialog.ShowAsync()` (store pages :552, :107), `_ = DebouncedSearchAsync(ct)` — all swallow errors (LoadQueue's `catch { }` at :326).
### Persistence smells
10. **No debounce** — every state change re-serializes the *entire* queue JSON on the UI thread; `_dirty` flag is vestigial. Progress bytes are only persisted when a state change happens to trigger a save, so a crash mid-download persists stale `BytesReceived` (harmless in practice since resume reads the partial file size).
11. **Silent drop of resolver/multi-file items on restart** (:267) — a tools-bundle download interrupted by app close just vanishes from the queue with no notification.
12. **`LoadQueue` race with fresh enqueues** — runs on a background thread while the UI is already usable; restored items are appended after newly enqueued ones (ordering interleaving, no corruption).
### Retry / robustness
13. **Retry only exists in the single-file fallback chain** (:565-610: primary → primary retry → alternate URL). `ProcessMultiFileAsync` has **no retry, no validation, no alternate source**.
14. **No dedup** — the same package can be enqueued multiple times (e.g., from list page and detail page, or after catalog reload creates new `StorePackage` instances with `InstallState = "idle"`); nothing checks the queue for an existing item with the same URL/destination.
15. **`ClearCompleted` also clears Failed/Cancelled** (:190-199) — naming lies.
16. **8-char GUID IDs** (`DownloadQueueModels.cs:245`) — birthday-collision risk with a long-lived queue.
17. `%TEMP%\TubaWinUi3_Winget` installers are never cleaned up.
### Resource management
18. **New `HttpClient` + handler per download** (`CreateHttpClient` :28 via `ProxyService.CreateClient`) — disposed correctly with `using` (:751, :500), and capped at 2 concurrent, so socket exhaustion is unlikely but it re-pays connection setup (no connection reuse across downloads). Contrast: `WingetStoreService._probeClient` (:25) and `ToolsBundleService._httpClient` (:25) are long-lived statics — inconsistent strategy.
19. **`DownloadQueueFlyout` never unsubscribes** from `Queue.CollectionChanged`/`QueueChanged` (:29-30) — fine only because the flyout is cached for the app lifetime (`MainWindow.xaml.cs:437-444`).
### Misc
20. `StorePackage.InstallState` is a magic string, not an enum or INPC (`StorePackage.cs:63-68`); UI state is driven by manually mutating `Button.Content`, duplicated nearly identically in two pages.
21. Two `MainWindow.xaml.cs` files exist — `MainWindow.xaml.cs` (repo root, :60) and `TubaWinUi3.WinUI3/MainWindow.xaml.cs` (:209) both call `DownloadQueueService.Initialize` (the root one appears to be a stale copy; double-init would re-register post-processors and re-trigger LoadQueue).
22. `WingetStoreService._resolvedUrlCache` is unbounded (session-scoped, minor).
23. `ToolsBundleDownloadDialog.ShowDownloadAsync` fires `_ = ResolveAndShowAsync()` then `await ShowAsync()` — dialog UI updates race with dialog visibility; benign but fragile.

- **`DownloadItem`** (`INotifyPropertyChanged`): `Id` (8-char guid), `DisplayName/Description/Glyph/Tag`, `State`, `Progress`, `ProcessingStatus`, `ErrorMessage`, `CompletedAt`; factories `CreateDirect / CreateWithResolver / CreateMultiFile`; internal `Cts`, `ResolvedUrl/FileName/Size`, `ResumePosition`, `SupportsResume`; `Reset()`/`PrepareResume()`.
- **States**: `Queued → Resolving → Downloading → (Paused) → Processing → Completed | Failed | Cancelled`.
- **`DownloadQueueProgress`** record: `BytesReceived, TotalBytes, Percentage, SpeedMbps, EstimatedRemaining`.
- **Entry points**: `Enqueue(displayName, downloadUrl, destinationPath, postProcessor, description, glyph, tag)`, `EnqueueWithResolver(..., Func<CancellationToken, Task<ResolvedDownloadUrl>> urlResolver, ...)`, `EnqueueMultiFile(...)` — all return the bound `DownloadItem` and start immediately (subject to the 2-slot semaphore).
- **Resume**: `.tubadl` partial files + HTTP `Range` header; if server returns non-206, partial is deleted and download restarts; `ResumePosition` updated during streaming; queue persisted to JSON (`ConfigManager.GetDownloadQueuePath()`) with dirty-flag + dispatcher-deferred `SaveQueue`, and interrupted items restored as `Paused` with progress on load.
- **Failover + validation**: `DownloadFileWithFallbackAsync` — primary source → auto re-download once → switch to `AlternateUrl` (GitHub) → aggregated error; `ValidateDownloadedFile` opens every zip entry, deletes + throws `InvalidDataException` on corruption to trigger re-download.
- **Post-processing**: `IDownloadPostProcessor` (`ExecuteAsync(file, dest, IProgress<string>, ct)`) with implementations `ArchiveExtractProcessor`, `InstallerLaunchProcessor`, `MoveToDestinationProcessor`, `ToolsBundleExtractProcessor` (atomic dir swap + backup/restore + copy fallback + retries), `CommunityToolInstallProcessor`, `UpdateInstallProcessor`, `DelegatePostProcessor`, `ChainedPostProcessor`; `PostProcessorRegistry` keys them by `DisplayName` for persistence.
- **Shared helpers**: `DownloadQueueService.FormatSize/FormatSpeed/FormatTime` (used app-wide, e.g. FormatConverterPage line 220/859); `ZipExtractHelper.ExtractTolerant` (zip-slip guard, dedupe, readonly-attribute clearing, per-entry retry, skip-list) — also directly unit-tested (`TubaWinUi3.Tests/ZipExtractHelperTests.cs`).
- **UI integration**: `Initialize(DispatcherQueue)` at startup; toasts on enqueue/complete/fail (swallowed in unpackaged mode); `ObservableCollection<DownloadItem> Queue` exposed for binding; `QueueChanged` event + `PendingCount`.
**Key takeaway for new store/download work**: don't build new download plumbing — enqueue into `DownloadQueueService` (direct URL, resolver, or multi-file) and bind/watch the returned `DownloadItem`; for batch UI, follow FormatConverterPage's `QueueItem`/`SetState`/per-item try-catch pattern; for tests, extract pure static parsing functions (string/JsonElement in → records out) mirroring `WingetStoreService`/`ToolsBundleService`.

378: internal static class ZipExtractHelper
379: {
380:     private const int EntryRetryCount = 3;
381:     private static readonly TimeSpan EntryRetryDelay = TimeSpan.FromMilliseconds(300);
382:
383:     /// <summary>
384:     /// 容错解压：逐条目处理，重复条目去重、文件/目录同名冲突时先移除冲突文件、
385:     /// 写入前清除只读属性、单条目瞬时失败自动重试，个别条目失败仅记录并跳过，
386:     /// 不影响其余文件。
387:     /// </summary>
388:     public static List<string> ExtractTolerant(string zipPath, string destinationDir,
389:         IProgress<string>? statusProgress = null)
390:     {
391:         var skipped = new List<string>();
392:         var seenPaths = new HashSet<string>(StringComparer.OrdinalIgnoreCase);
393:
394:         Directory.CreateDirectory(destinationDir);
395:
396:         using var archive = ZipFile.OpenRead(zipPath);
397:         foreach (var entry in archive.Entries)
398:         {
399:             var isDir = entry.FullName.EndsWith('/') || entry.Name.Length == 0;
400:             var fullName = entry.FullName.Replace('/', Path.DirectorySeparatorChar);
401:             var targetPath = Path.Combine(destinationDir, fullName);
402:
403:             if (!IsSafeTarget(destinationDir, targetPath))
404:             {
405:                 skipped.Add(entry.FullName);
406:                 continue;
407:             }
408:
409:             var dedupeKey = fullName.TrimEnd(Path.DirectorySeparatorChar);
410:             if (!seenPaths.Add(dedupeKey))
411:                 continue;
412:
413:             try
414:             {
415:                 if (isDir)
416:                 {
417:                     TryCreateDirectory(targetPath);
418:                     continue;
419:                 }
420:
421:                 var parent = Path.GetDirectoryName(targetPath);
422:                 if (!string.IsNullOrEmpty(parent))
423:                     TryCreateDirectory(parent);
424:
425:                 if (!TryExtractEntry(entry, targetPath))
426:                     skipped.Add(entry.FullName);
427:             }
428:             catch (Exception ex) when (ex is IOException or UnauthorizedAccessException)
429:             {
430:                 skipped.Add(entry.FullName);
431:             }
432:         }
433:
434:         TryClearReadOnlyAttributes(destinationDir);
435:         return skipped;
436:     }
437:
438:     private static bool IsSafeTarget(string root, string target)
439:     {
440:         try
441:         {
442:             var rootFull = Path.GetFullPath(root);
443:             var targetFull = Path.GetFullPath(target);
444:             return targetFull.StartsWith(rootFull, StringComparison.OrdinalIgnoreCase);
445:         }
446:         catch
447:         {
448:             return false;
449:         }
450:     }
451:
452:     private static void TryCreateDirectory(string dir)
453:     {
454:         if (Directory.Exists(dir)) return;
455:
456:         // 目标路径被同名文件占用：先移除该文件再建目录
457:         if (File.Exists(dir))
458:         {
459:             TryDeleteFile(dir);
460:         }
461:
462:         Directory.CreateDirectory(dir);
463:     }
464:
465:     private static bool TryExtractEntry(ZipArchiveEntry entry, string targetPath)
466:     {
467:         for (var attempt = 1; attempt <= EntryRetryCount; attempt++)
468:         {
469:             try
470:             {
471:                 if (File.Exists(targetPath))
472:                     TryClearReadOnlyAttribute(targetPath);
473:
474:                 entry.ExtractToFile(targetPath, overwrite: true);
475:                 return true;
476:             }
477:             catch (Exception ex) when (ex is IOException or UnauthorizedAccessException)
478:             {
479:                 if (attempt >= EntryRetryCount) return false;
480:                 Thread.Sleep(EntryRetryDelay);
481:             }
482:         }
483:         return false;
484:     }
485:
486:     public static void TryClearReadOnlyAttributes(string path)
487:     {
488:         try
489:         {
490:             if (File.Exists(path))
491:             {
492:                 TryClearReadOnlyAttribute(path);
493:                 return;
494:             }
495:             if (!Directory.Exists(path)) return;
496:
497:             TryClearReadOnlyAttribute(path);
498:             foreach (var file in Directory.EnumerateFiles(path))
499:                 TryClearReadOnlyAttribute(file);
500:             foreach (var dir in Directory.EnumerateDirectories(path))
501:                 TryClearReadOnlyAttributes(dir);
502:         }
503:         catch { }
504:     }
505:
506:     public static void TryClearReadOnlyAttribute(string path)
507:     {
508:         try
509:         {
510:             var attrs = File.GetAttributes(path);
511:             if ((attrs & FileAttributes.ReadOnly) != 0)
512:                 File.SetAttributes(path, attrs & ~FileAttributes.ReadOnly);
513:         }
514:         catch { }
515:     }
516:
517:     private static void TryDeleteFile(string path)
518:     {
519:         for (var attempt = 1; attempt <= EntryRetryCount; attempt++)
520:         {
521:             try
522:             {
523:                 TryClearReadOnlyAttribute(path);
524:                 File.Delete(path);
525:                 return;
526:             }
527:             catch (Exception ex) when (ex is IOException or UnauthorizedAccessException)
528:             {
529:                 if (attempt >= EntryRetryCount) throw;
530:                 Thread.Sleep(EntryRetryDelay);
531:             }
532:         }
533:     }
534: }

536: public sealed class ToolsBundleExtractProcessor : IDownloadPostProcessor
537: {
538:     private const int MaxAttempts = 3;      // 首次 + 自动重试 2 次
539:     private const int RetryDelayMs = 500;
540:     private const int CleanupAttempts = 3;
541:
542:     private readonly string? _version;
543:
544:     public string DisplayName => "解压工具包";
545:
546:     public ToolsBundleExtractProcessor(string? version = null)
547:     {
548:         _version = version;
549:     }
550:
551:     public async Task ExecuteAsync(string downloadedFilePath, string destinationPath,
552:         IProgress<string>? statusProgress, CancellationToken ct)
553:     {
554:         statusProgress?.Report("正在解压工具包...");
555:         await Task.Run(() => ExtractCore(downloadedFilePath, destinationPath, statusProgress), ct);
556:     }
557:
558:     private void ExtractCore(string downloadedFilePath, string destinationPath,
559:         IProgress<string>? statusProgress)
560:     {
561:         Exception? lastError = null;
562:
563:         for (var attempt = 1; attempt <= MaxAttempts; attempt++)
564:         {
565:             if (attempt > 1)
566:             {
567:                 statusProgress?.Report($"解压遇到文件占用，正在自动重试（第 {attempt}/{MaxAttempts} 次）...");
568:                 Thread.Sleep(RetryDelayMs * attempt);
569:             }
570:
571:             var extractDir = Path.Combine(Path.GetTempPath(), $"TubaWinUi3_Extract_{Guid.NewGuid():N}");
572:             try
573:             {
574:                 ExtractOnce(downloadedFilePath, destinationPath, extractDir, statusProgress,
575:                     allowCopyFallback: attempt == MaxAttempts);
576:                 return;
577:             }
578:             catch (Exception ex)
579:             {
580:                 lastError = ex;
581:                 TryDeleteDirectory(extractDir);
582:                 if (attempt >= MaxAttempts)
583:                 {
584:                     var message = ex.InnerException?.Message ?? ex.Message;
585:                     throw new IOException($"解压工具包失败（已自动重试 {MaxAttempts - 1} 次）：{message}", ex);
586:                 }
587:             }
588:         }
589:
590:         if (lastError is not null) throw lastError;
591:     }
592:
593:     private void ExtractOnce(string downloadedFilePath, string destinationPath, string extractDir,
594:         IProgress<string>? statusProgress, bool allowCopyFallback)
595:     {
596:         if (!File.Exists(downloadedFilePath))
597:             throw new FileNotFoundException("下载的文件不存在", downloadedFilePath);
598:
599:         try
600:         {
601:             statusProgress?.Report("正在解压文件...");
602:             var skipped = ZipExtractHelper.ExtractTolerant(downloadedFilePath, extractDir, statusProgress);
603:             if (skipped.Count > 0)
604:             {
605:                 statusProgress?.Report($"已跳过 {skipped.Count} 个无法解压的文件（可能被占用或只读）");
606:             }
607:         }
608:         catch
609:         {
610:             TryDeleteDirectory(extractDir);
611:             throw;
612:         }
613:
614:         var backupDir = destinationPath + "_bak";
615:
616:         try
617:         {
618:             if (Directory.Exists(destinationPath))
619:             {
620:                 TryDeleteDirectory(backupDir);
621:                 Directory.Move(destinationPath, backupDir);
622:             }
623:
624:             var destParent = Path.GetDirectoryName(destinationPath);
625:             if (!string.IsNullOrEmpty(destParent))
626:                 Directory.CreateDirectory(destParent);
627:
628:             try
629:             {
630:                 Directory.Move(extractDir, destinationPath);
631:             }
632:             catch
633:             {
634:                 TryRestoreDirectory(backupDir, destinationPath);
635:                 throw;
636:             }
637:
638:             TryDeleteDirectory(backupDir);
639:             try { File.Delete(downloadedFilePath); } catch { }
640:             ApplyCompletedState(destinationPath);
641:         }
642:         catch
643:         {
644:             if (!allowCopyFallback) throw;
645:
646:             // 兜底：目录原子替换行不通（文件被占用）时，逐文件复制覆盖
647:             statusProgress?.Report("正在使用文件拷贝模式完成安装...");
648:             TryRestoreDirectory(backupDir, destinationPath);
649:             try
650:             {
651:                 var skippedCount = CopyDirectoryContents(extractDir, destinationPath, statusProgress);
652:                 if (skippedCount >= Directory.GetFiles(extractDir, "*", SearchOption.AllDirectories).Length)
653:                     throw new IOException("目标目录不可写，文件拷贝全部失败");
654:
655:                 TryDeleteDirectory(extractDir);
656:                 try { File.Delete(downloadedFilePath); } catch { }
657:                 ApplyCompletedState(destinationPath);
658:             }
659:             catch (Exception fallbackEx)
660:             {
661:                 throw new IOException($"解压工具包失败：{fallbackEx.Message}", fallbackEx);
662:             }
663:         }
664:     }
665:
666:     private void ApplyCompletedState(string destinationPath)
667:     {
668:         if (!string.IsNullOrEmpty(_version))
669:         {
670:             Services.AppSettings.Set("ToolsBundleVersion", _version);
671:         }
672:
673:         Services.ToolCatalog.RefreshToolsRoot();
674:
675:         // 强制刷新侧边栏 / 标签页的工具分类（MSIX 内核安装完成后立即生效）
676:         if (App.MainWindow is MainWindow mainWindow)
677:         {
678:             mainWindow.DispatcherQueue.TryEnqueue(mainWindow.RefreshToolCategories);
679:         }
680:     }
681:
682:     private static void TryDeleteDirectory(string dir)
683:     {
684:         for (var i = 0; i < CleanupAttempts && Directory.Exists(dir); i++)
685:         {
686:             try
687:             {
688:                 // 只读文件会导致 Directory.Delete 抛异常，先清除属性
689:                 ZipExtractHelper.TryClearReadOnlyAttributes(dir);
690:                 Directory.Delete(dir, true);
691:                 return;
692:             }
693:             catch
694:             {
695:                 if (i < CleanupAttempts - 1) Thread.Sleep(300);
696:             }
697:         }
698:     }
699:
700:     private static void TryRestoreDirectory(string backupDir, string destinationPath)
701:     {
702:         if (Directory.Exists(destinationPath) && Directory.Exists(backupDir))
703:         {
704:             try
705:             {
706:                 ZipExtractHelper.TryClearReadOnlyAttributes(destinationPath);
707:                 Directory.Delete(destinationPath, true);
708:             }
709:             catch { }
710:         }
711:         if (Directory.Exists(backupDir) && !Directory.Exists(destinationPath))
712:         {
713:             try { Directory.Move(backupDir, destinationPath); } catch { }
714:         }
715:     }
716:
717:     private static int CopyDirectoryContents(string sourceDir, string destinationPath,
718:         IProgress<string>? statusProgress = null)
719:     {
720:         Directory.CreateDirectory(destinationPath);
721:         var files = Directory.GetFiles(sourceDir, "*", SearchOption.AllDirectories);
722:         var skipped = 0;
723:         foreach (var file in files)
724:         {
725:             var relative = Path.GetRelativePath(sourceDir, file);
726:             var target = Path.Combine(destinationPath, relative);
727:             var parent = Path.GetDirectoryName(target);
728:             if (!string.IsNullOrEmpty(parent))
729:                 Directory.CreateDirectory(parent);
730:
731:             if (!TryCopyWithRetry(file, target)) skipped++;
732:         }
733:
734:         if (skipped > 0)
735:         {
736:             statusProgress?.Report($"已跳过 {skipped} 个无法写入的文件（可能被占用或只读）");
737:         }
738:
739:         return skipped;
740:     }
741:
742:     private static bool TryCopyWithRetry(string source, string target)
743:     {
744:         for (var attempt = 1; attempt <= 3; attempt++)
745:         {
746:             try
747:             {
748:                 if (File.Exists(target))
749:                     ZipExtractHelper.TryClearReadOnlyAttribute(target);
750:
751:                 File.Copy(source, target, true);
752:                 return true;
753:             }
754:             catch (Exception ex) when (ex is IOException or UnauthorizedAccessException)
755:             {
756:                 if (attempt >= 3) return false;
757:                 Thread.Sleep(300);
758:             }
759:         }
760:         return false;
761:     }
762: }

Key design decisions:
**1. Multi-segment (分块) parallel download engine**
- New class `SegmentedDownloadEngine` (pure logic + testable helpers)
- Flow: HEAD/ranged GET probe → if server supports ranges (Accept-Ranges: bytes or successful 206) and size known and size > threshold (e.g. 4 MB) and segments >= 2 → split into N segments → download each segment in parallel to `.tubadl.{i}.part` files → merge into final file → validate (SHA256/zip)
- If server doesn't support ranges → fallback to single-stream (existing path)
- Per-segment resume: track segment offsets in a metadata file (`.tubadl.json`) alongside partial files, so restart can resume each segment
- Progress: aggregated bytes across segments, throttled 300ms, speed computed from aggregate
- Cancellation: shared ct per item; segment tasks honor ct
- Segment failure: retry individual segment (up to 2 retries), then fail whole download → fallback chain handles source switch

namespace TubaWinUi3.Services.Downloads;
public sealed record DownloadSegment(int Index, long Start, long Length, long DownloadedBytes)
{
public long End => Start + Length - 1;
}
public static class SegmentPlanner
{
public const long MinSegmentSize = 1L << 20; // 1MB min per segment
public const long DefaultThresholdBytes = 8L << 20; // 8MB
public static int ClampSegmentCount(long totalSize, int requested, long minSegmentSize = MinSegmentSize)
{
if (totalSize <= 0 || requested <= 1) return 1;
var maxBySize = (int)Math.Min(int.MaxValue, Math.Max(1, totalSize / Math.Max(1, minSegmentSize)));
return Math.Clamp(requested, 1, maxBySize);
}
public static bool ShouldSegment(long totalSize, int segmentCount, long thresholdBytes = DefaultThresholdBytes)
=> totalSize >= thresholdBytes && segmentCount > 1;
public static List<DownloadSegment> Plan(long totalSize, int segmentCount, long minSegmentSize = MinSegmentSize)
{
var n = ClampSegmentCount(totalSize, segmentCount, minSegmentSize);
var result = new List<DownloadSegment>(n);
if (totalSize <= 0) { result.Add(new(0, 0, 0, 0)); return result; }
long baseLen = totalSize / n;
long remainder = totalSize % n;
long start = 0;
for (int i = 0; i < n; i++)
{
long len = baseLen + (i < remainder ? 1 : 0);
result.Add(new DownloadSegment(i, start, len, 0));
start += len;
}
return result;
}
// meta json
public static string BuildSegmentMetaJson(string url, long totalSize, IReadOnlyList<DownloadSegment> segments) {...}
public static bool TryParseSegmentMetaJson(string json, out SegmentMeta meta) {...}
}
public sealed record SegmentMeta(string Url, long TotalSize, long[] DownloadedBytes)
{
public bool Matches(string url, long totalSize) => TotalBytes==totalSize && string.Equals(Url,url,OrdinalIgnoreCase);
}

{

private int _limit;
private int _active;
public Task WaitAsync(CancellationToken ct)
{
lock (_sync)
{
if (_active < _limit) { _active++; return Task.CompletedTask; }
var tcs = new TaskCompletionSource(TaskCreationOptions.RunContinuationsAsynchronously);
var node = _waiters.AddLast((tcs, ct));
// registration outside lock...
return tcs.Task;
}
}
public void Release()
{
lock (_sync)
{
_active--;
while (_waiters.Count > 0)
{
if (_active >= _limit) break;
var (tcs, token) = _waiters.First.Value; _waiters.RemoveFirst();
if (tcs.Task.IsCompleted) continue; // cancelled
_active++;
tcs.SetResult();
break; // one permit per release
}
if (_active < 0) _active = 0;
}
}
public void Resize(int newLimit)
{
lock (_sync)
{
_limit = Math.Max(1, newLimit);
while (_active < _limit && _waiters.Count > 0)
{
var (tcs, token) = _waiters.First.Value;
_waiters.RemoveFirst();
if (tcs.Task.IsCompleted) continue;
_active++;
tcs.SetResult();
}
}
}
}
